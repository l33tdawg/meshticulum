# Explicit HAT SPI clock request

The public file example accepts `--hat-spi-hz 4000000` on HAT only. Omitting it retains the existing 1 MHz constructor/configuration sequence. Explicit 1 MHz is also accepted; other values and any explicit value on USB are refused. FileHardware binds this option across loans.

LinuxHAT continues to require the exact Orange Pi 5 Plus SPI/GPIO binding and a device-tree `spi-max-frequency` value of 1 MHz. That check identifies the reviewed board configuration. The opt-in requests 4 MHz through SPI_IOC_WR_MAX_SPEED_HZ, reads SPI_IOC_RD_MAX_SPEED_HZ back, and requires an exact match before any transfer. Every SPI_IOC_MESSAGE carries that same explicit request. A failed ioctl or mismatched readback closes the acquired handles through the original exception path. No device-tree edit or reboot occurs.

Readback is the kernel's accepted userspace setting, not measured SCLK. Upstream Linux 6.1 spidev temporarily sets the device maximum for spi_setup and restores it afterward; its per-open requested speed remains separate. SPI core fills a missing transfer speed from the device, but clamps an explicit speed against the controller maximum. Rockchip selects an even divider rounded upward, making its generated clock no higher than requested. See [spidev](https://github.com/torvalds/linux/blob/v6.1/drivers/spi/spidev.c), [SPI core](https://github.com/torvalds/linux/blob/v6.1/drivers/spi/spi.c), and [Rockchip driver](https://github.com/torvalds/linux/blob/v6.1/drivers/spi/spi-rockchip.c).

The [Semtech SX1261/2 datasheet section 8.2](https://files.waveshare.com/wiki/SX1262-XXXM-LoRaWAN-GNSS-HAT/DS_SX1261-2_V1.2.pdf) gives a 16 MHz SPI maximum. Waveshare's [official HAT demo](https://files.waveshare.com/wiki/SX1262-XXXM-LoRaWAN-GNSS-HAT/Sx126x_lorawan_hat_code.zip) requests 7.8 MHz. These sources support investigating 4 MHz; they do not qualify the actual Orange Pi wiring or prove its vendor kernel matches upstream. Actual 6.1.115-vendor-rk35xx package 26.8.2 has known provenance but no verified exact SPI source commit in this review. Functional read tests and any physical-clock measurement remain separate hardware work.

No PHY values, packet sequencing, authority checks, owner guards, lease/deadline, attempt or airtime accounting change. Source ioctl fixtures are not hardware qualification or throughput evidence.
