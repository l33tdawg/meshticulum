# Conditional RadioLib erratum writes

`prepare_firmware.py prepare --skip-unchanged-erratum-writes` enables an experimental Heltec-only optimization. RadioLib still reads the IQ and sensitivity workaround registers on every existing call and computes the required value. It writes only when that value differs. A changed value still uses the original checked write; read failures still return immediately. No mode, IRQ, FIFO, receive guard, deadline, or accounting operation changes.

The strict boolean option defaults off. Omission preserves the previous application bytes and identity, including `mtb1-df5ddf1fc5` with its original profile/SPI/header options. Enabling the option applies a separately pinned patch to `SX126x.cpp`; it composes with the existing bulk-SPI patch to `ArduinoHal.cpp`. The generated forced-include header binds the option and patch digest into application identity, enables it only for Heltec ESP32 board1, and leaves XIAO board2 disabled. External macro overrides and inconsistent target definitions fail compilation. Build validation checks the generated header, identity, vendor result, option and both forced includes before invoking the compiler.

The new tests compile the actual patched vendor functions with ASan/UBSan in both default-off and enabled modes. They compare all register-byte values and IQ/modem selections, fresh-read counts, corrected values and read/write failure propagation. Recipe tests cover composition, identity, strict options, source drift and target gating. The local exact-vendor integration tests require the retained reviewed vendor tree; they explicitly skip if that tree is unavailable.

This is a source candidate. Skipping up to three short register writes per TX/RX cycle may reduce overhead; no physical improvement is claimed. Firmware preparation, compilation, installation and RF testing each retain their existing separate controls.
