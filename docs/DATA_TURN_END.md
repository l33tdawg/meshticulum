# Authenticated DATA turn end (bench opt-in)

`radio_file.py --data-turn-end` requires both peers' admitted route to contain the exact `meshticulum.data-turn-end-capability.v1` record. The route binds that record into the grant context. It requires the existing explicit train32 policy and operation limits. The flag alone grants nothing; it must match the route. The default remains off.

An admitted marker uses authenticated outer kind `DATA_TURN_END=4` around the original MT3 DATA bytes. It has the same byte geometry as DATA and is charged as DATA. This changes ACK eligibility, not frozen flow, SACK, credit, delivery receipts, grant deadlines or native guards. Diagnostics preserve semantic `outer_kind=DATA` and separately record `wire_kind=DATA_TURN_END`.

The sender considers a marker only inside an already established native turn. It seals admission before cipher callbacks when the exact candidate fills the current credit/window, consumes the remaining object bytes, or occupies the final train32 position. The seal retains the original token, generation, deadline, count and candidate. Ciphertext is bound once to that seal. Further DATA, including caught callback reentry, cannot reopen the turn. Authenticated ACK progress does not clear it. Only successful physical drain and the existing reverse-turn retirement clear the seal. Refusal, uncertain write or mutated binding retains containment and paid debt; these paths may terminate the operation. First/single-admission turns without an established identity retain the existing quiet fallback rather than moving CLOCK or reservation order.

The receiver authenticates and persists replay state before interpreting a marker as DATA. Only matching admitted inner DATA that advances normal ACK work can release the quiet barrier. An older outer counter after newer admitted DATA cannot release it. Normal ACK scheduling, authority checks and paid transmission still apply. Lost or rejected markers retain the existing quiet/cap fallback. The native 5 ms receive interval, 100 ms reverse floor, 2 s original train deadline, queue-eight limit and host pending-three limit are unchanged.

Source tests cover real route admission, encrypted flow delivery, changed outer headers, malformed inner DATA, replay, old markers, callback reentry and option mutation, pending authenticated ACKs, refusal/unknown writes and retirement mutation. A paired SF5/BW500/preamble32 model covers clean and identical loss scripts. It demonstrates ACK eligibility and marker coverage; synthetic native completion events do not qualify RF timing, throughput or target CPU overhead. Early eligibility can change the number of ACK attempts: it does not imply a refund or guarantee fewer transmissions.
