# Public mixed-path qualification boundary

Meshticulum provides generic authenticated radio/TCP carriers, original-deadline and replay controls, MR1 resource blocks, publisher/content verification and verified-piece resume. Device provisioning, finite Linux jobs, native application policy, fleet orchestration and deployment belong to **[Lantern](https://github.com/l33tdawg/sage-lantern)**, which depends on this library.

The detailed operator runbook is [Lantern's coordinated public LoRa/IP pilot](https://github.com/l33tdawg/sage-lantern/blob/codex/meshticulum-boundary/docs/lantern/MESHTICULUM_PUBLIC_PILOT.md). Its [`lantern_meshticulum` integration](https://github.com/l33tdawg/sage-lantern/tree/codex/meshticulum-boundary/software/meshticulum-integration) owns the controller, native context/provisioner, quarantine handling, recipient verification and finite radio/TCP entries. Meshticulum retains no copies of those application implementations.

The mixed path remains under qualification. A source test, loopback TCP transfer, read-only preflight, artifact hash or prepared grant cannot establish a current device handoff or physical delivery. Before execution, the host application must establish current exclusive ownership and a finite authorization window, observe actual boots/firmware/service lifetimes, and retain bounded cleanup and debt evidence. This page authorizes no radio, private-message provider or production service.

Qualification must prove actual C→A LoRa→B IP request/reply with independently verified recipient content; bounded IP loss followed by fresh LoRa admission and reuse of verified pieces; and return to IP only when a fresh verified timing sample establishes its advantage. Every child keeps the original host-local resource deadline, peer/service bindings and prior attempt costs. A new session cannot reuse old nonce/replay state, renew expired work or refund radio/stream-byte debt.

Keep local RF completion, kernel acceptance, authenticated peer receipt, durable bytes and publisher/private application acceptance separate. Preserve failed and unavailable observations. Historical [radio results](PERFORMANCE.md) do not qualify a newer bundle or the full path; native private-backend and matched MeshCore/Reticulum requirements also remain open. See [hardware ownership](HARDWARE.md), [architecture](ARCHITECTURE.md) and [the roadmap](ROADMAP.md).
