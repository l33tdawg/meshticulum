# Owned DIO1 edge wake

The HAT worker can wait for a GPIO hint instead of repeatedly checking the DIO1 level and repeating the full authority callback. The ordinary receive operation still checks fresh authority and reads the radio IRQ; a GPIO event is never a packet claim.

LinuxHAT requests a rising edge on DIO1 (offset 5, request index 3) within its existing exclusive four-line GPIO request. RESET, RF switch and BUSY flags are unchanged. The request has a 16-event kernel buffer and a nonblocking descriptor. The transport checks the current DIO1 level. When high, it drains at most sixteen 48-byte GPIO notifications nonblockingly and returns the observed high hint, including when the drain returns EAGAIN. When low, it performs at most one select with the remaining original timeout and reads at most sixteen events. It does not issue SPI commands, drain radio IRQs, rearm RX, reset, transmit, create a thread or change RF authority. Stale events can cause a harmless early receive poll. GPIO event loss is not packet loss evidence; overflow may reduce wake quality but cannot authorize a packet or extend the wait.

The worker samples the original wait start, checks live authority, bounds the wait by five milliseconds and the original lease, then checks live authority again after the callback. Callback mutation, revocation and expiry still refuse before receive. Revocation observation during an idle blocking wait can be delayed until that wait returns, at most the original five-millisecond requested blocking budget; it is not polled every 250 microseconds. Kernel scheduling and the mandatory fresh checks may add wall-clock latency beyond that requested blocking budget. No new operation is allowed without those checks. The existing polling/fallback behavior remains for transports without the event hook.

This is source qualification only. The exact target kernel GPIO interrupt support and wiring must be independently qualified before operational use; an unsupported edge request fails closed. No physical throughput improvement is established by callback-count tests. The companion ABI checker now compares the event structure size and rising-edge flag against Linux headers.

Primary ABI documentation: [GPIO v2 event read](https://www.kernel.org/doc/html/latest/userspace-api/gpio/gpio-v2-line-event-read.html). It specifies enabling edge detection in the request, bounded kernel buffering, readable-fd notification, nonblocking reads and overflow behavior. No new radio status interpretation is introduced.

The high-level drain avoids leaving the same GPIO notification queued after the ordinary radio poll clears its IRQ. It adds one bounded read to a high-level return but can remove a later stale-notification wake and its empty host-pump iteration. A new edge consumed in the same batch cannot suppress this return: the high branch always asks for a fresh ordinary receive poll. Edges arriving after the read remain queued; excess records beyond16 remain queued and may still cause early polls. There is no drain-until-empty loop and no change to packet, radio IRQ, lease, authority or ownership logic. Actual prevalence and net latency gain require measurement; model tests do not attribute the observed header errors to stale events.
