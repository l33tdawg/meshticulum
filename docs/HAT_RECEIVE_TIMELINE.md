# Optional HAT receive timeline

The public `radio_file.py transfer --hat-receive-timeline` option records bounded software timing for the HAT receive path. It defaults off and is rejected for USB. It does not change PHY settings, receive guards, authority, original deadlines or paid-attempt accounting. The worker option is `receive_timeline=True`; no extra SPI operation or packet hash computation is added.

`BenchFlow.snapshot()['hat_receive_timeline']` contains at most4096 receive-call rows. Each row holds diagnostic host-monotonic start/end timestamps, outcome, up to4 nonzero IRQ observations already read by the driver, up to4 rearm intervals, and an optional accepted packet hash. The hash is reused from the existing authenticated DATA/ACK/CONTROL flow event. Physical packets rejected by authentication have no accepted hash anchor. Rearm intervals cover `HATWorker.receive` only; initialization and transmit restoration are excluded.

The public success result and failure attribute contain summary metadata with `rows_in_flow_snapshot:true`; they do not duplicate the rows. Callers must retain the full flow snapshot to preserve the detailed evidence. No result claims packet-loss attribution or external RF timing. Accepted packet hashes can align this receiver timeline with existing sender events, but do not establish a synchronized cross-host clock.

Diagnostics add two monotonic clock reads per receive call, one per recorded nonzero IRQ and two per recorded rearm interval. Default-off calls make none of these clock reads. This work consumes CPU and can perturb scheduling; report diagnostic overhead when comparing throughput. The diagnostic clock never feeds deadlines or authorization. Exceptions, invalid/negative/non-integer clocks or regression mark evidence incomplete. Existing worker errors still fence/contain and propagate normally.

Eviction, detail overflow, clock errors or an active receive call make `complete:false`. Ring eviction is explicit and does not claim the retained tail is complete. Consumers requiring complete timing must reject these cases while retaining all available evidence and paid costs. With current bounded fields, the tested maximum4096-row schema is below2.8MB. The paired campaign harness reduces only the receiver flow ring to1024 entries (sender2048/physical4096 unchanged), reserving1025 serialized bytes per receiver flow entry and65536 other snapshot bytes within the unchanged4MB full-snapshot ceiling. This calculation is not a universal bound for arbitrary surrounding snapshots or future fields: exact final serialization must still be checked and failures retained.

Source tests cover SPI/on-off parity, successful packets and empty polls, header/timeout observations, read/rearm failure cleanup, revocation, overflow, clock failure/regression, disabled clock calls, and real encrypted public-file DATA/CONTROL acceptance and malformed-packet rejection. Model tests do not qualify physical throughput or a hardware execution window.
