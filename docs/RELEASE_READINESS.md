**Status on 2026-10-11: alpha unreleased; project announcement prepared separately.** The development package is `0.1.0`. Python version `1.0.0a1`, Git tag `v1.0.0-alpha` and release artifacts remain proposals for a later reviewed release. The source repository, documentation and website can introduce the project before that release, after the [project-preview publication checks](PROJECT_PREVIEW.md). Exact candidate source/tests/artifacts and paired Lantern dependencies retain their separate qualification requirements.

## What this alpha would mean

The proposed public alpha is an installable experimental transport/resource package with reviewed boundaries, reproducible artifacts and explicit limitations. It would include the frozen MT05 flow, reusable bounded radio workers, authenticated TCP source prototype, MR1 public-resource interfaces, verified-piece resume and offline recipient-encrypted envelopes. Announcing the source project does not establish these release gates.

[SAGE Lantern](https://github.com/l33tdawg/sage-lantern) owns private SAGE adapters, protected capture and policy, native Linux node/pilot entry points, provisioning, runtime bundles and device/fleet deployment. Those implementations are not distributed in the Meshticulum package. Lantern consumes an explicitly pinned Meshticulum dependency; Meshticulum does not import Lantern or require its SDK.

The TCP prototype has loopback controls, and Lantern has modeled native entry-point controls. A separate finite native campaign at historical pins core `6605ba714ce414445673b40bfcfe93fe467b86aa`, Lantern [a41851a](https://github.com/l33tdawg/sage-lantern/commit/a41851a4301008bd840a8508187a59a150eeaa0e) and runtime `d3194a9` completed a public C→A LoRa→B IP request and reverse reply with **977 independently verified public bytes**. [The native milestone record](IP_TRANSPORT.md#recorded-native-public-milestone) gives the full identities and scope; [Lantern’s pilot guide and evidence](https://github.com/l33tdawg/sage-lantern/blob/c596664b41e6ae1bd37cf64591fb7bd827533900/docs/lantern/MESHTICULUM_PUBLIC_PILOT.md#evidence-and-cleanup) retain the operator boundary. Earlier radio goodput measurements remain bound to their older runtime.

A separate fresh failure/resume campaign observed TCP loss after **512 stream bytes** and preserved its first verified piece. It refused fresh LoRa **before ARM/TX** because a fixed **90-second lease** exceeded approximately **85 seconds remaining**. That earlier attempt did not complete resume. Its lease-sizing fix was source-tested and undeployed at that checkpoint; the failure remains historical at the pins above.

A later fresh native campaign at core `a89c1ca6fdf1865d61367cf3a8d59ac1ab50cb39`, Lantern runtime code [379025e](https://github.com/l33tdawg/sage-lantern/commit/379025e177619ee3ffd51ef8d5ae0b2bc27dd54e) and runtime `856570c` completed loss, fresh C↔B LoRa request/reply and measured IP return within **one original 160-second window**. It rejected the partial reply after an injected **512-stream-byte loss**, preserved the first verified piece and independently verified **four 977-byte pieces / 3,908 useful bytes** before the unchanged expiry. Ten sessions ended with **twenty terminal, retired native children** and **three terminal owned management masters**. The read-only journal/holder/service audit passed and handback completed before **11:35 UTC on 2026-10-10**. [Full execution pins and scope](IP_TRANSPORT.md#recorded-native-public-resume-and-ip-return) · [Lantern evidence](https://github.com/l33tdawg/sage-lantern/blob/2f96d9029f972e665286209d9883418d431ab1d0/docs/lantern/evidence/meshticulum-native-resume-20261010.json).

The tiny service samples—**54.349727 seconds** for the resumed LoRa piece and **9.529958 seconds** for fresh IP—include management preparation and final radio ACK windows. They establish the campaign’s current path choice, not sustained carrier capacity or a matched upstream benchmark. Private production, measured RF airtime/energy/EIRP, firmware source/deployed-image equivalence, notice/source/relinking closure and release gates remain open. The project intentionally retains its disclosed [development history](REPOSITORY_HISTORY.md). **The alpha is not ready.**

An alpha does not promise stable wire/API compatibility, autonomous routing, a MeshCore/Reticulum packet gateway or production private dispatch. It also does not complete the active programme. Its hardware, private-backend, benchmark and public-publication gates remain in [ROADMAP.md](ROADMAP.md).

## Proposed version and artifacts

For the later alpha candidate, use Python version **`1.0.0a1`** and, only after readiness review and a release decision, Git tag **`v1.0.0-alpha`** on the same exact commit. The GitHub release title is **`1.0.0-alpha`**. The project-preview source remains `0.1.0`; no alpha tag exists to consume.

Prepare these artifacts for review:

- A wheel and source distribution built from the candidate commit, with SHA-256 hashes, dependency versions, Apache-2.0 license and retained notices. Check installation and canonical imports independently of the SAGE parent checkout.
- A reviewed Meshticulum distribution manifest containing reusable core code and required support files. Exclude Lantern/SAGE adapters, native deployment tools, protected data and product configuration. Any public-only host-runtime archive used for qualification is a separately owned Lantern artifact, with its own exact dependency, source manifest and launcher hash; building it grants no device or dispatch authority.
- Candidate validation records: standalone tests, frozen-flow verification, documentation/benchmark checks, Python CI matrix and installed-artifact smoke checks. Pair them with Lantern's compatible-SDK and native integration records for the exact dependency pin. Record skips, failures, toolchain versions and scope alongside hashes.
- Release notes stating experimental behavior, supported entry points, original-deadline/replay/debt semantics, known limitations and retained benchmark conditions. Link every claimed result to evidence; keep unavailable measurements null.
- Firmware preparation/build records from the [explicit primary-input recipe](FIRMWARE_RECIPE.md), tied to the exact input lock, patch, recipe, source manifest and target output hashes. Preserve failed attempts and identify the macOS-arm64 host/CLI environment. These artifacts do not imply flashing, native acceptance, bit-identical rebuilds or complete linked-source notices.

For source-archive repeatability, retain the original backend outputs and normalize their timestamps/owner metadata with [`normalize_sdist.py`](../tools/normalize_sdist.py), using an explicit `--source-date-epoch` fixed to the candidate commit. The tool preserves file bytes and permissions, rejects duplicate/unsafe paths and refuses to overwrite an existing output. Compare two independently built normalized archives and inspect their member manifests. A raw backend archive can vary in timestamps even when its content matches; retain that failed byte-comparison alongside the normalized result. This packaging step establishes no native or release acceptance.

The [extraction validation record](../provenance/VALIDATION.json) is a historical checkpoint, not proof that a later candidate passed. The current Meshticulum artifact and its paired Lantern integration each require their own records. Moving application code cannot carry qualification forward automatically.

- [ ] Review covers the exact Meshticulum candidate, one-way dependency and excluded application files, plus the paired Lantern commit for native provisioning, request binding, local quarantine and publisher verification. - [ ] Standalone tests and the Python 3.11–3.13 [CI matrix](../.github/workflows/tests.yml) pass on that commit. Run [`verify_frozen_flow.py`](../tools/verify_frozen_flow.py), [`check_docs.py`](../tools/check_docs.py) and [`verify_benchmark_report.py`](../tools/verify_benchmark_report.py).
- [ ] Lantern's private/native integration controls pass against its documented compatible SDK and exact Meshticulum pin. Report modeled ownership/MockTransport limitations; do not infer native qualification. No private adapter tests or SDK installation extra are required by the Meshticulum package.
- [ ] The Meshticulum wheel and source distribution reproduce their recorded manifests, contain required support files and preserve frozen-flow pins. A paired Lantern host bundle has independent evidence. Inspect all distributed contents for unintended parent-application, private-data or third-party artifacts.
- [ ] Expiry, boot binding, revocation, unknown writes and lifetime debt remain intact through cancellation, restart and fresh child admissions. Public quarantine cannot become a verified piece without request, manifest and publisher checks.
- [ ] Documentation distinguishes kernel acceptance, RF completion, authenticated peer receipt, durable bytes and application acceptance. Historical radio medians are about 1.2 kB/s; 1.5 kB/s remains a target, with upstream comparisons based on cited published figures and their stated conditions.
- [ ] The selected firmware recipe validates every archive and patch/license hash, compiles the named targets from the candidate inputs and retains logs/ELF/map/output identities. Inspect the actual source distribution for `inputs.lock.json`, CLI requirements, patch and supplementary license; independently review linked SDK/runtime notices, corresponding source and any required relinking materials.

## Gates that remain open

Earlier development commits contain the extracted Lantern implementations. The project intentionally preserves that reviewed history, including old PR references, and explains it in [repository history](REPOSITORY_HISTORY.md). Current source and distributed package contents must remain Meshticulum-only, with retained history and credential-scan scope reviewed before publication. The [boundary record](../provenance/REPOSITORY_BOUNDARY.json) identifies the moved implementations. Historical code is not a supported current deployment path.

Lantern owns native execution and deployment. The public mixed exchange and later successful loss/resume/IP-return campaign are recorded above; the earlier lease refusal remains a separate failed attempt. Further native runs require a fresh coordinated device window, bounded cleanup and independent recipient publisher verification. Each campaign must retain debt, reuse only verified pieces under the original deadline and use fresh verified timing when selecting an IP return. A completed finite campaign creates no reusable dispatch authority.

Private production still requires qualified native owner/consent/revocation and private transport, including encrypted-backend admission. The owner selected comparison with published MeshCore/Reticulum figures; running counterpart benchmark campaigns is not required. Review each cited figure’s hardware, settings, privacy, completion semantics and request/response/ACK/retry scope, keeping missing conditions and incomparable quantities explicit. Sustained useful RF goodput and latency remain separate qualification requirements; actual RF airtime, energy and EIRP remain unmeasured.

The [firmware recipe](FIRMWARE_RECIPE.md) specifies 14 primary archive inputs, isolated preparation and two named targets. The HWCDC patch retains its file's Apache-2.0 grant; overall LGPL-2.1-or-later framework text and SDK/per-file exceptions are separate. The [validation record](../provenance/FIRMWARE_RECIPE_VALIDATION.json) binds the historical two-file application and its corrected recipe/lock to fresh reproduction of binary/ELF/bootloader/partitions for both targets in runs 05/06 on one pinned macOS-arm64 host; maps differ. Earlier copied-dependency controls produced different binaries. Those runs close only that historical one-host build check. The current four-file application, including the GFSK profiles, needs fresh target builds and recorded outputs. Neither source tests nor the historical builds establish deployed-image equivalence, native qualification or complete notices.

The [linked-notice audit](FIRMWARE_LINKED_NOTICES.md) supplies allocated-section archive/member inventories and selected primary/runtime texts for those exact artifacts. It leaves dirty SDK source correspondence, exact member/per-file terms, GNU/newlib applicability, corresponding source/relinking materials and release review unresolved. Retained WiFi/Bluetooth object contributions do not establish active services or native qualification.

Target-bound build evidence, complete SDK/runtime source/notice closure and release review remain required for paired Lantern hardware qualification and distributed artifacts. Meshticulum's own source notices and repository boundary must be reviewed before the project announcement; wheel and release-artifact review remain required for the later alpha. The project preview distributes no prebuilt device firmware. A raw-radio application tag is not the whole firmware identity. Public source and a website cannot waive inherited requirements or stand in for the full [roadmap](ROADMAP.md).

The finite native public mixed-path and loss/resume/IP-return milestones are recorded, but the alpha is not ready. Source/deployed-image correspondence, complete notices and source/relinking closure for the exact distributed artifacts and release review remain required. The reviewed current-tree boundary and disclosed retained development history are also project-preview prerequisites. Lantern must retain the exact Meshticulum, integration and runtime identities for each campaign. Private native owner/consent and transport, sustained performance and latency remain open. Claims against published upstream figures require their documented scope. The proposed alpha version is `1.0.0a1`; the native milestones create no alpha tag or release authority.

When these public-alpha gates are satisfied, notify the user with the exact candidate commit, review link, artifact hashes and validation scope. Preparing the candidate does not authorize changing visibility, creating a tag or publishing packages. See the [draft release notes](../CHANGELOG.md).
