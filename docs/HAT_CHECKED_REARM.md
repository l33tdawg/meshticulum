# Checked HAT receive rearm handoff

`radio_file --hat-checked-rearm` is an explicit, default-off LoRa HAT experiment. After a successful checked RX drain, one subsequent rearm may reuse the completed standby and IRQ-clear proof. This removes only the repeated SetStandby/GetStatus and ClearIrqStatus/GetStatus/GetIrqStatus transactions. Packet parameters, IRQ mask, finite SetRx, its status checks, all finite-RX errata, authority checks and original deadlines remain in place.

The proof is consumed before rearm checks or I/O and cannot authorize a second reuse. A transport activity epoch advances before each SPI transfer, GPIO output operation and close, including failed attempts. The original transport callbacks and epoch reader are bound; ordinary mutation/deletion is refused while tracking. Opt-in driver transactions check state and activity across clock/BUSY callbacks. The handoff records the checked-drain state before optional diagnostic callbacks. Any intervening driver/raw transport command, TX, configuration, reset, switch, error or changed state invalidates reuse or produces containment. A clock callback changing hardware or state during the first optimized transfer is rejected before that transfer.

This is a local, single-owner API invariant, not a Python security sandbox. Direct malicious ioctl calls, class-global monkeypatching followed by restoration, or reflective object/closure mutation are outside the proof. Existing ownership checks remain mandatory. No token is a grant, refund, lease extension, or proof of physical delivery.

Source tests execute the actual LinuxHAT transfer/GPIO methods and SX1262 opcode path over mocked ioctl responses. They cover raw authority-callback activity, late clock mutations, full surviving command-byte parity, checked-drain and optimized-transfer faults, finite near-deadline timers, revocation and expiry. They do not qualify target hardware.

A local four-by-100 receive-cycle model measured 26 SPI transactions per default cycle and 21 with the option. Proof checking adds Python CPU work: local median thread CPU was approximately136µs versus332µs per modeled cycle. This fixture excludes real target GPIO/SPI/BUSY and scheduling costs. Five fewer transactions do not establish a net target speedup, reduced packet loss, or 4000 B/s. Target qualification remains pending; existing firmware and wire protocol are unchanged.
