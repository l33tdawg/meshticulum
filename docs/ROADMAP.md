# Remaining qualification

The existing Meshticulum programme remains active. Moving source into its own repository does not close any of its physical or release requirements.

1. Qualify the public finite service runner on current hardware under a fresh coordinated device window, including disarm, rollback and settled worker debt.
2. Add and qualify authenticated IP transport with original peer/expiry/replay bindings and explicit IP accounting. Do not label socket writes as RF completion or charge IP bytes as radio airtime.
3. Measure C→A LoRa→B IP, IP loss followed by fresh LoRa admission and verified-piece resume, and return to a locally measured faster IP route. Preserve failed and unavailable observations.
4. Qualify the optional private SAGE integration against the real encrypted backend and native owner, including original intention, capture, replay, expiry, consent and uncertain-write recovery.
5. Run matched Meshticulum/MeshCore/Reticulum benchmarks on the same hardware, settings, useful encrypted payloads and finite budget. Report request, response, ACK, retry and reverse-medium cost. The target remains 1–1.5 kB/s useful encrypted RF goodput without completion or latency regressions.
6. Produce a standalone reproducible firmware/BSP recipe, third-party license inventory and release review before public/production publication.

Source estimates, loopback HTTP, simulated carrier success, type identity, manifest hashes and passing tests must remain distinct from physical and production evidence.
