# Transport source update

This candidate carries the reusable SDK and firmware from Core [`2b9db9e`](https://github.com/l33tdawg/meshticulum/commit/2b9db9e71dfa7d115d4e465225893b828c760171), plus the public examples, release-status corrections and source-package fix from [`9d4ac04`](https://github.com/l33tdawg/meshticulum/commit/9d4ac04e2aab6c3e92b994942dda2abc44f85d15), onto public main. It retains the public website, branding, source boundary and disclosed extraction history. The original project preview used `0.1.0`; this candidate uses **`1.0.0a1`** metadata and does not publish an alpha or carry forward hardware qualification from another source/runtime pair.

| Component | Source now available | Boundary |
| --- | --- | --- |
| Radio | Explicit GFSK125/GFSK250 profiles, matching serial/SPI workers and raw-radio firmware support; bounded ARM deadlines, earlier return to receive, a checked 2 KiB USB receive queue with bounded bulk reads, and DIO1 task notification alongside periodic MCU service checks. | Profiles grant no RF authority. Retained build records apply only to their recorded application identities; this source update establishes no new physical timing or throughput result. |
| TCP | Explicitly admitted v2 sender readiness, authenticated before ordinary receiver credit starts. | Legacy v1 stays unchanged. READY consumes the original byte/frame limits and extends no deadline. Native provisioning belongs to the consuming application. |
| Resources | MB1 byte-bundle encoding, manifest/hash verification, bounded file finalization and transport descriptors; explicitly selected 32 KiB public-response capability. | Source and file tests do not establish native bundle throughput. Existing default MR1 limits remain unchanged. |
| Private protocol | Opaque forwarding of MPF2 records under held carrier authority, with bounded lifetime and one-use idle cleanup delegation. | The relay supplies no endpoint private keys, SAGE policy, device provisioning or production dispatch. |
| Reliable flow | Existing MT05 flow and flow-port source. | Their accepted byte pins remain unchanged. |
| Own-hardware examples | Manual app-only flashing/rollback, a bounded raw-file example and a signed five-part 100 kB MB1 service example with retained file clocks and boot bindings. | The application supplies independently approved finite grants and coordinates the part pairs. Source/model checks do not qualify a device, sustained goodput or a release. |

The [SDK guide](SDK_GUIDE.md) retains its offline example. [Device setup](DEVICE_SETUP.md), the [firmware recipe](FIRMWARE_RECIPE.md) and [app-only flashing guide](FLASHING.md) distinguish build evidence from deployment and rollback. The [signed bundle example](../examples/BUNDLE.md) retains the original grants, boot identities, monotonic file end and attempt debt. The [post-quantum prototype](POST_QUANTUM.md) remains a separate experiment; this update does not make post-quantum cryptography the default.

Existing [performance records](PERFORMANCE.md) remain bound to their original samples and timing definitions. This source update establishes no new speed comparison, sustained throughput, private native qualification or firmware-release result. The [alpha gates](RELEASE_READINESS.md) remain open.

Meshticulum remains independent of Lantern and the SAGE SDK. [SAGE Lantern](https://github.com/l33tdawg/sage-lantern) owns product policy, private adapters, native jobs, provisioning and deployment. A consuming application must pin the exact integrated commit and verify its required source hashes before repeating its own integration and native checks.
