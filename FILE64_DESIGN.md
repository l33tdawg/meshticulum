# Explicit64KiB single-operation file candidate

Source-only, based on a5f65d2. Hardware activation requires separate review. Frozen flow and firmware remain unchanged.

The legacy file manifest v1 and16KiB chunk/cache behavior remain default. New `--file64` is an exact boolean opt-in on manifest, transfer and assemble. It selects manifest schema `meshticulum.example-radio-file.v2` with exactly65,536 bytes and one descriptor at index0 whose object_id and chunk SHA both equal the whole-file SHA. No arbitrary larger chunk sizes or multi-chunk v2 are admitted. The full manifest is pinned by its exact input SHA and existing file-window record.

A new top-level `file_capability` is accepted only in bench-run (never service-run). Its exact keys bind schema `meshticulum.file64-capability.v1`, max_object_bytes65536, max_total_frames512 and manifest_sha256. It requires an explicit existing operation_limits record. Authority independently requires the exact single64KiB object shape and includes capability in the authenticated route digest; current-plan/route snapshots already reject later mutation. Missing capability preserves16KiB admission. Conflicting public32/service use is refused. This capability changes memory/logical-frame admission only; max_frames remains<=512, operation attempts/airtime stay explicit and bounded by the unchanged radio profile, and original deadlines/boot counters/queue8/train24 remain unchanged.

Capability-aware object/frame helpers feed both authority contract construction and BenchFlow. Frozen ReliableFlow is configured with512 logical-frame ceiling (340 required at193 useful/frame); retry ceiling, SACK32/window32 and all transmission accounting stay unchanged. Smaller explicitly admitted physical budgets may still terminate safely; source code must not auto-enlarge them.

A distinct opt-in VerifiedFile64 cache subclass reuses existing atomic data-before-metadata publication, hash verification and fsync. It accepts only a singleton64KiB descriptor and has a separate cache namespace; default VerifiedChunks remains16KiB. Existing receipt confirmation derives its context from the complete new manifest plus chunk index and original issue/expiry, so peers with different capabilities/manifests cannot share authenticated receipt state. One transfer_chunk invocation creates one worker/session/grant and sends all64KiB without part restarts.

Negative tests cover missing/wrong/bool capability fields, service conflict, absent operation limits, mismatched manifest pin, legacy rejection, non-singleton/short/oversized v2, changed cache content, out-of-bound memory/frame limits, exact CLI opt-in and original route mutation. A modeled sender/receiver test must deliver64KiB through unchanged frozen flow with one endpoint lifetime and finite original authority; loss/retry/expiry tests retain existing semantics. Full standalone suite and frozen-flow verification are required before candidate commit. No throughput or physical-delivery claim follows from these tests.
