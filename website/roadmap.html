Recorded / Public SDK file transfers

100 kB verified twice.
1.95–2.03 kB/s including startup.

The public SDK completed two fresh 100,000-byte files, each across five signed parts on a direct GFSK250 link. The recipient independently verified the publisher, every part and each whole-file SHA-256. A separate fresh 23,900-byte file reached 2.535 kB/s through authenticated receipt.

Above the alpha floor for this tested path.

All ten receiver confirmations were accepted. The files had zero and one DATA retransmissions respectively and zero new receiver drops; all twenty endpoint children exited successfully. This initial repeat leaves sustained-capacity evidence and release review open.

The SX1262 HAT sender and Heltec V4 MCU receiver were about one metre apart. GFSK at 250 kb/s is a separate modulation from LoRa. These samples provide no field-range result; measured RF airtime, energy and EIRP remain unavailable. Earlier LoRa and upstream observations keep their own conditions on the comparison page.

In progress / The next release

The next gate is a usable alpha.

Speed matters when the transfer finishes correctly. The alpha floor is above 1,000 useful encrypted bytes per second with sender startup included, on a declared supported path. Setup, verification and cleanup time must also remain visible.

  • Performance

    Repeat useful delivery above the floor.

    Repeat the new complete SDK file transfers on the supported hardware, measuring startup and coordination cost alongside delivery. Report useful decoded bytes, ACK and retry cost, completion and latency within the original deadlines. Keep unsuccessful samples in the record.

  • Reliability

    Finish safely when a link fails.

    Exercise loss, final-ACK recovery, expiry, replay refusal and interruption. Preserve verified work, original peer and boot bindings, and attempt debt. Prove disarm and ownership closure; an uncertain write keeps its reservation.

  • Deployment

    Make firmware and the SDK usable together.

    Extend the three finite public SDK file samples with installation and recovery checks on the declared supported hardware, binding the exact source, firmware and package versions. Keep app-only backup and rollback instructions, clean package installation, required notices, corresponding source and relinking materials with the artifacts.

  • Qualification

    Keep each advertised path within its evidence.

    Extend radio and authenticated TCP coverage, including mixed-path failure and resume. Native private owner, consent, replay and forward-secrecy qualification remain open. The consuming application must qualify its integration; source tests cannot stand in for it.

Later / Beyond the alpha baseline

Measure the next step.

Optional stretch

4 to 5 kB/s useful delivery.

Pursue faster profiles only with verified radio and firmware support. Measure completion, range, retries and power alongside throughput. This stretch target is separate from the alpha floor and has no promised date.

Feasibility work

Post-quantum and hybrid protocols.

Study handshake size, fragmentation, memory, processing cost and key distribution before choosing a deployment path. The current default protocols use classical cryptography. A prototype or a passing source test is not a security qualification.

Read the post-quantum work

Published MeshCore and Reticulum figures help define questions worth measuring. Their hardware, workload, encryption and timing conditions belong beside any comparison. A faster number on one path does not establish a general speed or security ranking.

Not published / Alpha artifacts

Release after the checks pass.

The repository and GitHub Pages site are public. An alpha tag, package release and firmware release assets have not been published. The checkout's 1.0.0a1 metadata prepares a candidate; it does not mark acceptance.

A release needs an exact source revision, reviewed package and firmware contents, reproducible build records, required license materials and installation instructions that match the supplied artifacts. The existing qualification and release requirements stay in force.

One family / Separate projects

A transport others can build on.

Meshticulum is the reusable protocol, cryptography, reliable flow, drivers and verified-resource SDK. SAGE Lantern owns its product, STL and printing files, private SAGE adapters, device policy and deployment. Lantern's launch is separate; the dependency runs from Lantern to Meshticulum.

Created and maintained by Dhillon Andrew Kannabhiran (l33tdawg) under the SAGE Foundation. SAGE supplies the wider memory and governance project.
