Recorded / Public SDK file transfers

100 kB to 1 MB verified.
2.11, 2.22 and 2.23 kB/s.

The signed-bundle path completed fresh 250,000-, 500,000- and 1,000,000-byte files on the direct GFSK250 HAT-to-MCU link. Every recipient verified the publisher, all parts and the exact whole-file SHA-256. Final sender-startup-inclusive rates were 2.111, 2.216 and 2.230 kB/s (16.889, 17.725 and 17.838 kbit/s).

The original 1 MB run reached 1.750 kB/s while the sender host's production LLM engine held CPU4 at roughly 95%; that sample remains in the record. Excluding CPU4 from the benchmark reduced mean part time from 10.97 to 8.66 seconds and raised the fresh 1 MB control to 2.230 kB/s. All 74 receiver confirmations across the final three files were accepted.

SF7 is 1.431× faster than SF8 on the matched bench link.

Three same-payload pairs at BW500/CR4/5 measured median sender-ARM-to-receipt rates of 1.044 kB/s (8.351 kbit/s) at SF7 and 0.729 kB/s (5.834 kbit/s) at SF8. All six chunks and authenticated receipts passed, and the final batch kept one MCU boot with no unknown, fenced or dropped attempts. This is a finite profile comparison, not a range or upstream ranking.

A first one-request HTTP gateway also fetched http://example.com/ through unit A's internet connection and returned it over the radio. Unit C's links text browser rendered the page in 53.3 seconds; the same request with a 30-second timeout failed. The body and both radio directions verified. This is an application gateway, not transparent IP, HTTPS CONNECT or a TUN interface.

Recorded / Clean installation and continuation

Install the wheel.
Continue verified work.

A separate fresh 100 kB file completed from the published wheel on Linux aarch64, using normal virtual environments with Python 3.11.2 on the receiver and 3.14.4 on the sender. Isolated imports and all 67 runtime files matched the installed distribution; neither endpoint loaded an editable checkout, SDK zip or system site packages.

After part 0 was verified and both processes closed, the coordinator paused for 5.011 seconds. Fresh processes continued parts 1–4 under the original grants and 240-second window. The receiver checked and reused verified pieces. This demonstrates continuation after a completed piece; in-flight crash recovery remains unproved.

The installed wheel delivered 1.74 kB/s (13.92 kbit/s) including startup, while scope-to-closure measured 1.61 kB/s (12.91 kbit/s). All five receiver confirmations were accepted, with one DATA retransmission and zero new raw receive discards. Publisher and whole-file verification passed; all ten endpoint children exited successfully, and owned endpoints closed and disarmed. Both hosts had staged source packs, while receiver acceptance checked the bytes delivered over the radio. Installation, dependency acquisition, file preparation, signing and staging preceded the radio window.

An earlier installed trial stopped after four verified parts (95,600 bytes) when a harness condition required an unchanged raw receive-discard counter. All eight started children closed successfully, but the fifth part never started. The corrected harness records that counter as a diagnostic while preserving receipt, hash, journal and deadline requirements. The successful file is fresh, and the earlier attempt debt remains retained.

Published / Baseline alpha

The source-build alpha is public.

Speed matters when the transfer finishes correctly. The 1.0.0-alpha release records useful encrypted delivery above 1 kB/s (8 kbit/s) with sender startup included on the declared near-bench GFSK250 path. The next work extends completion, recovery and hardware coverage while keeping setup, verification and cleanup time visible.

  • Performance

    Repeat useful delivery above the floor.

    Repeat the new complete SDK file transfers on the supported hardware, measuring startup and coordination cost alongside delivery. Report useful decoded bytes, ACK and retry cost, completion and latency within the original deadlines. Keep unsuccessful samples in the record.

  • Reliability

    Finish safely when a link fails.

    Exercise loss, final-ACK recovery, expiry, replay refusal and interruption. Preserve verified work, original peer and boot bindings, and attempt debt. Prove disarm and ownership closure; an uncertain write keeps its reservation.

  • Deployment

    Extend the published setup path.

    The clean installed-wheel check demonstrates full-file completion and continuation after a verified piece on the declared GFSK250 path. The published alpha supplies the SDK and a source-build path with app-only backup and rollback instructions and required notices. Broader hardware and in-flight recovery remain separate work; optional prebuilt firmware needs its own source, object, relinking and notice review.

  • Qualification

    Keep each advertised path within its evidence.

    Declare the supported radio path and its setup, timing and recovery limits. Wider mixed-path failure/resume and native private owner, consent, replay and forward-secrecy qualification remain programme work. The consuming application must qualify its integration; a public SDK alpha does not complete that work.

Later / Beyond the alpha baseline

Measure the next step.

Optional stretch

4 to 5 kB/s useful delivery.

Pursue faster profiles only with verified radio and firmware support. Measure completion, range, retries and power alongside throughput. This stretch target is separate from the alpha floor and has no promised date.

Feasibility work

Post-quantum and hybrid protocols.

Study handshake size, fragmentation, memory, processing cost and key distribution before choosing a deployment path. The current default protocols use classical cryptography. A prototype or a passing source test is not a security qualification.

Read the post-quantum work

Published MeshCore and Reticulum figures help define questions worth measuring. Their hardware, workload, encryption and timing conditions belong beside any comparison. A faster number on one path does not establish a general speed or security ranking.

Published / Alpha artifacts

The source-build alpha is live.

The v1.0.0-alpha prerelease is published from source 673eb60 with package version 1.0.0a1. It includes the tested SDK wheel, normalized source archive, firmware source-build guide, project notices, public proof records, release manifest and SHA-256 checksums.

No compiled firmware or third-party dependency wheels are included. Optional prebuilt binaries retain a separate distribution checklist. The release is experimental and does not complete wider sustained-capacity, mixed-path, native private or field-range qualification.

One family / Separate projects

A transport others can build on.

Meshticulum is the reusable protocol, cryptography, reliable flow, drivers and verified-resource SDK. SAGE Lantern owns its product, STL and printing files, private SAGE adapters, device policy and deployment. Lantern's launch is separate; the dependency runs from Lantern to Meshticulum.
